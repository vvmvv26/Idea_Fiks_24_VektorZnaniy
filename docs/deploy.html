От чистого сервера до работающего бота

Ручная установка без Docker: подготовка Ubuntu-сервера, перенос кода, бесплатная локальная модель через Ollama, запуск как системный сервис и проверка. Каждую команду можно скопировать и выполнить как есть.

ℹБыстрее — одной командой через скрипт deploy.sh или в Docker: см. разделы «Установка на сервер одной командой» и «Запуск в Docker» в README.md. Эта инструкция — для тех, кто хочет поставить бота без Docker.
Платформа: МАКС (библиотека maxapi) ОС: Ubuntu 24.04 / Debian 12+ Время: ≈ 30–40 минут Бюджет: 0 ₽ (без платного API)

Что именно разворачиваем

Один процесс на Python (vektor_znaniy_max_bot.py), который держит долгоживущее соединение с серверами МАКС (long polling) — входящих портов открывать не нужно. Состояние живёт только в оперативной памяти процесса, базы данных нет. Рядом, по желанию, — Ollama: бесплатная языковая модель, работающая локально на этом же сервере.

Шаг 1

Подготовка сервера

Подключаемся по SSH, обновляем систему, заводим отдельного пользователя без прав root — бот не должен работать от имени администратора.

на сервере, от root или через sudo
sudo apt update && sudo apt upgrade -y
sudo apt install -y python3 python3-venv python3-pip curl git

# отдельный пользователь для бота — не root
sudo useradd -m -s /bin/bash vektorbot
sudo mkdir -p /opt/vektor-znaniy
sudo chown vektorbot:vektorbot /opt/vektor-znaniy
ℹPython 3.11 или новее обязателен: этого требуют версии библиотек из requirements.txt. В Ubuntu 24.04 уже стоит Python 3.12. Проверить версию: python3 --version.
Шаг 2

Перенос кода на сервер

Проще всего клонировать репозиторий прямо на сервер — папка /opt/vektor-znaniy из шага 1 пока пустая, и бот окажется ровно там, где его ждут следующие шаги.

на сервере, от имени vektorbot
sudo -iu vektorbot
git clone https://github.com/vvmvv26/Idea_Fiks_24_VektorZnaniy.git /opt/vektor-znaniy

Для приватного репозитория GitHub попросит логин и персональный токен доступа (вместо пароля) — либо настройте SSH-ключ и клонируйте по ссылке git@github.com:....

Запасной вариант без GitHub — скопировать папку bot/ с компьютера через scp:

на своём компьютере
scp -r vektor-znaniy/bot vektorbot@ВАШ_СЕРВЕР:/opt/vektor-znaniy/

Должна переехать вся папка bot: все .py-файлы, папка assets (эмблема для документов) и .env.example, а также requirements.txt из корня репозитория — рядом с папкой bot. Файл .env с настоящими секретами создаётся прямо на сервере в шаге 5 — его саму по себе копировать не нужно.

Шаг 3

Виртуальное окружение и зависимости

на сервере
# дальше — от имени vektorbot
sudo -iu vektorbot
cd /opt/vektor-znaniy/bot

python3 -m venv venv
source venv/bin/activate
pip install --upgrade pip
pip install -r ../requirements.txt
ℹВиртуальное окружение держит зависимости бота отдельно от системного Python — стандартная практика, ничего специфичного для этого проекта.
Шаг 4

Токен бота в МАКС

Токен получаем не на сервере, а в самом мессенджере МАКС — на телефоне или в десктоп-приложении.

  1. Откройте диалог с @MasterBot внутри МАКС.
  2. Отправьте команду /create и следуйте подсказкам.
  3. Укажите имя и ник бота — ник должен заканчиваться на _bot или bot.
  4. @MasterBot пришлёт токен доступа — скопируйте его, он понадобится в следующем шаге.
Шаг 5

Настройка .env

на сервере, в /opt/vektor-znaniy/bot
cp .env.example .env
nano .env

Впишите настоящий токен из шага 4:

MAX_BOT_TOKEN=полученный_токен_без_кавычек
⚠Ограничьте права на файл — в нём секреты: chmod 600 .env. Без ключей LLM_API_KEY/LLM_API_BASE бот уже полностью рабочий: он выдаёт готовый промт и кнопки на бесплатные веб-чаты. Реальные ответы прямо в боте включает шаг 6.
Шаг 6

Локальный ИИ через Ollama (опционально, но рекомендуется)

Официальный скрипт сам ставит Ollama и сразу регистрирует её как systemd-сервис — отдельно ничего настраивать не нужно.

на сервере, от sudo
curl -fsSL https://ollama.com/install.sh | sh

# проверяем, что сервис поднялся
sudo systemctl status ollama

# скачиваем модель (один раз, ≈ 2 ГБ)
ollama pull qwen2.5:3b-instruct
Какую модель выбрать под ресурсы сервера
МодельРазмерКогда брать
qwen2.5:1.5b-instruct≈ 1 ГБменьше 3,5 ГБ RAM; отвечает быстрее, но проще и чаще ошибается
qwen2.5:3b-instruct≈ 2 ГБот 3,5 ГБ RAM, рекомендуется: на 2 ядрах ответ около 2 минут
qwen2.5:7b-instruct≈ 4,5 ГБесть видеокарта или ≥16 ГБ RAM

Проверить, что модель действительно отвечает:

curl http://127.0.0.1:11434/api/generate -d '{
  "model": "qwen2.5:3b-instruct",
  "prompt": "Скажи одним словом: тест пройден",
  "stream": false
}'

В .env для этого уже стоят рабочие значения по умолчанию — трогать не нужно:

LLM_API_KEY=ollama
LLM_API_BASE=http://localhost:11434/v1
LLM_MODEL=qwen2.5:3b-instruct
⛔Не открывайте Ollama наружу. По умолчанию она слушает только 127.0.0.1 — так и должно оставаться. Не задавайте OLLAMA_HOST=0.0.0.0: у Ollama нет встроенной авторизации, и любой в сети или интернете сможет использовать вашу модель и удалять её файлы.
Шаг 7

Запуск как системный сервис

Прямой запуск python vektor_znaniy_max_bot.py в терминале умирает при разрыве SSH-сессии. Правильный способ — systemd-сервис: сам перезапустит бота при сбое и при перезагрузке сервера.

создать /etc/systemd/system/vektor-znaniy.service, от sudo
[Unit]
Description=Vektor Znaniy MAX bot
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=vektorbot
WorkingDirectory=/opt/vektor-znaniy/bot
ExecStart=/opt/vektor-znaniy/bot/venv/bin/python vektor_znaniy_max_bot.py
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
включить и запустить
sudo systemctl daemon-reload
sudo systemctl enable vektor-znaniy
sudo systemctl start vektor-znaniy
sudo systemctl status vektor-znaniy
ℹТокен и настройки бот читает сам из .env в рабочей папке (через python-dotenv) — прописывать их отдельно в unit-файле не требуется.
Шаг 8

Проверка работы

  • В МАКС найдите своего бота по нику и отправьте /start — должно появиться меню выбора роли.
  • Выберите «Я учитель» → «Учебный материал» → план урока. С Ollama бот предложит «🤖 Ответ здесь» или «📋 Промт для другой нейросети»; без неё сразу пришлёт промт с кнопками бесплатных чатов.
  • Проверьте «Спросить ассистента»: задайте вопрос и нажмите «Проще» под ответом (нужна Ollama).
  • Проверьте «Поиск по материалу»: пришлите короткий текстовый файл и задайте вопрос по нему.
  • Проверьте «Проверка ответа»: пришлите тестовый ответ ученика.
  • Проверьте «Тест» → «По моему материалу»: пришлите параграф и скачайте тест в .docx.
  • Убедитесь, что процесс не падает: journalctl -u vektor-znaniy -f во время всех проверок.
Шаг 9

Обновление кода

Когда меняется сам бот (новая версия файла), обновляем код и перезапускаем сервис:

# с GitHub: на сервере, от имени vektorbot
cd /opt/vektor-znaniy && git pull

# либо без GitHub — с компьютера через scp (папка целиком, .env на сервере не затрагивается):
scp -r vektor-znaniy/bot/*.py vektor-znaniy/bot/assets vektorbot@ВАШ_СЕРВЕР:/opt/vektor-znaniy/bot/

# на сервере
sudo systemctl restart vektor-znaniy
sudo systemctl status vektor-znaniy

Если менялся requirements.txt — перед перезапуском:

sudo -iu vektorbot
cd /opt/vektor-znaniy/bot && source venv/bin/activate
pip install -r ../requirements.txt --upgrade
Шаг 10

Безопасность — короткий чек-лист

  • Бот работает от отдельного пользователя vektorbot, не от root.
  • .env имеет права 600 и не лежит ни в каком общедоступном месте (не в веб-корне, не в публичном репозитории).
  • Ollama слушает только 127.0.0.1 — не задавайте OLLAMA_HOST=0.0.0.0 без отдельного прокси с авторизацией.
  • Входящие порты для самого бота не нужны — long polling инициирует соединение сам бот. Файрвол можно держать закрытым на вход.
  • Промты не содержат и не запрашивают персональные данные учеников (152-ФЗ) — загруженные материалы живут только в памяти процесса и стираются по /start или через 30 минут.
